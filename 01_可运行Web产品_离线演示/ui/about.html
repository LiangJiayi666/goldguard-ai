GoldGuard AI · 产品说明与 AI 方法

黄金产业链网络信息与合规风险排查 · AI Native 投资产品创新（开放命题 第 14 题）

本产品为笔试作品。页面数据全部为构造/脱敏数据，不对应任何真实企业；产品不输出涨跌预测、收益承诺或买卖建议。

1. 问题、用户与非目标

要解决的问题

黄金价格与产业链企业风险信息（备案、官网、社媒、公告、舆情）分散且噪声大；人工尽调周期长、覆盖不全、口径不一、难以留痕。传统搜索只给链接，规则引擎只命中关键词，都无法回答「这条信息说明什么、传导到哪里、下一步核验什么」。

目标用户

黄金企业客户经理、贵金属投顾/产品经理、合规与审计人员（机构侧优先）。

非目标（明确不做）

  • 不输出确定性涨跌预测或收益承诺；
  • 不自动通过客户准入或授信，不替代人工尽调与审批；
  • 不把网络传闻当结论，不把模型推断伪装成事实。

成功标准（MVP 待实测）

单企业初筛耗时较人工下降；风险卡片引用完整率 ≥95%；高风险事件召回率 ≥90%；正式输出人工复核覆盖率 100%；无依据结论率 ≤3%。以上为验收目标，非既成业务结果。

2. 为什么必须是 LLM / Agent，而不是规则或搜索

能力规则引擎搜索引擎GoldGuard AI
召回多源信息仅预设关键词返回链接，不结构化多源召回 + 去重 + 实体对齐
理解语义与话术否否识别「保本/高息回购」等类资金池话术
跨文档推理传导否否建立 事件→企业→产品/黄金 的传导链
按受众生成合规表达模板固定否同源多表达，措辞经合规校验
可追溯与可审计部分否每条结论回指来源、时点、口径

3. AI 原生工作流

用户问题 / 新增企业 ↓ 任务分解 Agent：识别对象、时间范围、风险主题、输出格式 ↓ 检索 Agent：召回备案、官网、社媒、公告、规则 ↓ 证据 Agent：去重、抽取实体与事件、校验来源与时点 ↓ 分析 Agent：建立 事件→黄金/企业/产品 传导链，区分事实与推断 ↓ 合规 Agent：适当性、措辞、引用完整性、拒答降级 ↓ 人工复核：采纳 / 修改 / 标记误报 / 转人工 ↓ 输出：风险卡片 / 情景 / 客户说明 / 审批摘要 + 审计留痕 ↓ 反馈回流：误报、漏报、修改进入评测集

4. 数据、状态、工具与风险控制闭环

环节本产品中的实现
数据备案 / 官网 / 社媒 / 公告 / 规则，均有来源、时点、口径；缺失即标「待核实」
工具ICP 备案查询、官网抓取、OCR、社媒账号发现与核验、关键词与风险研判
状态企业级状态机 + 阶段进度，失败重试与终态判定，过程可回放
反馈人工复核结果改变结论状态，并写入审计事件
风险控制事实/推断分栏、引用强制、模型不可用时降级并标注、数据缺失不判「正常」

5. 失败条件与合规边界

明文失败与降级

  • 数据缺失/接口失败：输出「待核实」，不静默判定「正常」（见示例企业 G）；
  • LLM 不可用：降级为本地保守关键词规则，并标注「把握度低、需人工复核」（见示例企业 H）；
  • 来源仅摘录无全文：证据状态标 partial，不得作为唯一关键证据；
  • 证据冲突：并列展示支持/反对，不自动择一，要求复核。

合规边界

不提供个性化买卖指令；不承诺收益；不自动通过准入；不将传闻作结论；最小化采集个人信息；保留人工复核与申诉。

6. 如何体验

  1. 返回 风险驾驶舱；
  2. 点击「开始排查」，观察 12 个阶段推进与实时日志；
  3. 点击任一企业 → 切换到「AI 证据链」标签，查看事实证据、推断、不确定项、改变结论的条件；
  4. 点击「采纳 / 修改 / 标记误报 / 转人工」体验人工复核闭环；
  5. 在「示例企业G」「示例企业H」上观察数据缺失与模型降级的处理方式。
