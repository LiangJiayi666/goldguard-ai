## 2. 快速开始

### 2.1 离线演示产品（无需任何依赖）

```bash
cd 01_可运行Web产品_离线演示
python run.py
# 打开 http://127.0.0.1:8765
python run.py --host 0.0.0.0 --port 8000   # 供容器/局域网访问
```

只要求系统自带 **Python 3.8+**（用了 `http.server` / `urllib` 等标准库），无需 `pip install`。

**体验路径**：首页驾驶舱 →「开始排查」看 12 阶段推进 → 点企业 →「AI 证据链」标签 →「采纳/修改/标记误报/转人工」。
重点反例：**示例企业G（数据缺失→待核实）**、**示例企业H（LLM 不可用→降级并标注）**。

### 2.2 原版完整工程（真实流水线，需装依赖）

原版工程是一套 Windows 桌面流水线，安装与使用完全遵循 `安装使用指南.pdf`：

1. 解压 `02_原版源码_完整工程/` 到**无中文、无空格**的路径（如 `D:\icbc_gold`）；
2. 双击 `install.bat`：自动装 Python 3.11.9、创建 `.venv`、装依赖、装 Playwright Chromium、自检 ICP(16181)/OCR(16191) 服务；
3. 配置两个文件（`install.bat` 会从模板生成）：
   - `config/companies.txt`：每行一个企业全称；
   - `config/llm_config.txt`：`base_url` / `api_key` / `model`（LLM 是风险判定的必需项）；
4. 双击 `run.bat` 跑全链路，或双击 `dashboard.bat` 在看板（`http://127.0.0.1:18080`）里点「开始排查」；
5. 抓社媒前先双击 `refresh_dy_login.bat` / `refresh_ks_login.bat` / `refresh_xhs_login.bat` 扫码登录。

### 环境变量

离线演示产品**不需要任何环境变量或密钥**。原版工程不使用环境变量，配置集中在 `config/` 两个 txt（见指南第 2 节）。
**任何 API Key 都不应提交到仓库**；`.gitignore` 已忽略 `config/llm_config.txt` 与 `.env`。

## 3. 产品选择与定位

### 3.1 为什么选这个场景

黄金同时具备**投资属性**与**产业链企业属性**：一端是金价/宏观/避险，另一端是黄金珠宝、回收、精炼、贸易企业的经营与合规风险。现实中这两端的信息是割裂的——投资者看行情、客户经理做尽调、合规人员查处罚，各自为战，信息不共享、口径不统一、结论难追溯。

GoldGuard AI 选择以**黄金产业链企业的网络公开信息与合规风险**为切入口，做成一台「风险雷达 + 证据引擎」：
把备案、官网、社媒、公告、舆情等碎片信息，变成**可解释、可追溯、可人工复核**的风险卡片，直接服务黄金相关的授信、尽调、投资研究与合规审查。

### 3.2 目标用户

| 用户 | 核心任务 | 产品价值 |
|---|---|---|
| 黄金企业客户经理 | 授信/合作前快速排查企业风险 | 把「先搜资料再凭经验判断」变成「先看风险地图再定向核验」 |
| 黄金回收/珠宝业务合规岗 | 识别高息回购、资金池、冒名账号 | 命中类资金池话术并给出证据与处置建议 |
| 贵金属投顾 / 产品经理 | 生成合规、匹配客户的风险说明 | 同源证据 + 合规措辞 + 人工确认后输出 |
| 合规与审计 | 复核、留痕、申诉 | 每条结论附来源、时点、规则与复核记录 |

### 3.3 非目标（明确不做）

- 不做确定性涨跌预测、不承诺收益、不提供买卖建议；
- 不自动通过授信/客户准入，不替代人工尽调与审批；
- 不把网络传闻当结论，不把模型推断伪装成事实；
- 不在本阶段处理真实客户敏感信息（全程使用构造/脱敏数据）。

### 3.4 成功标准（MVP 验收目标，非既成结果）

单企业初筛耗时较人工下降 ≥50%；风险卡片引用完整率 ≥95%；高风险事件召回率 ≥90%；正式输出人工复核覆盖率 100%；无依据结论率 ≤3%。以上均为**待实测目标**。

## 4. AI 的角色与工作流（为什么必须是 LLM / Agent）

AI 不是产品末端的问答入口，而是贯穿核心业务：

```text
用户问题 / 新增企业
   ↓  任务分解 Agent：识别对象、时间范围、风险主题、输出格式
   ↓  检索 Agent：召回备案、官网、社媒、公告、规则
   ↓  证据 Agent：去重、实体对齐、校验来源与时点、标注 verified/partial/unavailable
   ↓  分析 Agent：建立 事件→黄金/企业/产品 传导链，区分事实与推断
   ↓  合规 Agent：适当性、措辞、引用完整性；无可靠证据则拒答/降级
   ↓  人工复核：采纳 / 修改 / 标记误报 / 转人工
   ↓  输出：风险卡片 / 情景 / 客户说明 / 审批摘要 + 审计留痕
   ↓  反馈回流：误报、漏报、修改进入评测集
```

对比传统方案：

| 能力 | 规则引擎 | 搜索引擎 | GoldGuard AI |
|---|---|---|---|
| 多源召回 | 仅预设关键词 | 只返回链接 | 多源召回 + 去重 + 实体对齐 |
| 语义理解（“保本/高息回购”话术） | 否 | 否 | 是 |
| 跨文档推理传导 | 否 | 否 | 是 |
| 合规表达生成 | 模板固定 | 否 | 同源多表达 + 合规校验 |
| 可追溯审计 | 部分 | 否 | 每条结论回指来源/时点/口径 |

## 5. 数据来源与口径

- **离线演示产品**：全部为 `data/fixtures.json` 中的**构造/脱敏数据**，企业名、域名、账号、证据均为虚构，时刻固定，可复现。
- **原版工程**：数据来源为公开渠道——工信部 ICP 备案公开查询、企业官网/公开页面、抖音/快手/小红书公开主页、公开新闻/公告；LLM 仅用于关键词生成与风险研判。
- 每条证据必须带 **来源、观察时点、口径、状态**；来源缺失或仅摘录时降级为 `partial`，不得作为唯一关键证据；数据缺失输出「待核实」。
- 详见 `docs/04_数据来源与口径.md`。

## 6. 合规与风险边界

- 不提供个性化买卖指令；不承诺收益；
- 不自动通过准入，风险评分只用于排序与提示；
- 不将传闻作结论；未验证信息单独标注；
- 最小化采集个人信息，采用脱敏与访问审计；
- 保留人工复核与申诉：用户可查看来源、修改结论、反馈错误；
- **失败/降级必须显式**：数据缺失=`待核实`；LLM 不可用=本地规则降级并标注；证据冲突=并列展示不自动择一。

详见 `docs/05_合规与风险边界.md`。

## 7. 已知边界与未做事项

**已知边界**
1. 离线演示产品的「开始排查」是**确定性离线模拟**，用于演示状态机/阶段推进/复核闭环，不调用真实外部接口；
2. 原版完整工程**未包含**大体积二进制件：`vendor/whl/`（离线依赖轮子）、`ICP_Query/model_data/*.onnx`（验证码模型，约 94MB）、`ICP_Query/.git`、`pipeline_output/`、`.venv/`。这些由 `install.bat` 自动安装/生成，或从上游 `HG-ha/ICP_Query` 获取（详见 `02_原版源码_完整工程/README_原版安装与使用.md`）；
3. 原版运行需要 Windows + 社媒登录态 + LLM Key + 约 10GB 磁盘，属环境相关，不影响离线演示产品；
4. ICP_Query 为第三方开源子工程，其 `config.yml` 中的 `admin/admin123` 为**上游默认口令**，部署前必须修改。

**未做事项（诚实声明）**
- 未接入真实生产数据与真实客户账户；
- 未做正式的业务指标实测（转化率、召回率等均为验收目标）；
- 未实现多租户权限、计费、SLA 等企业化能力；
- 未训练自有模型（采用成熟检索增强 + 规则 + 人工复核组合）。
