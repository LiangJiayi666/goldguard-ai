# 05 · 合规与风险边界

产品原则：**辅助判断，不替代责任。** 事实、推断与不确定信息必须分开；失败与降级必须显式。

## 一、六条硬边界

1. **不提供个性化买卖指令**：输出情景、风险与观察指标，最终决策由用户或持牌人员作出；
2. **不承诺收益**：所有预测都包含假设、期限、风险与不确定性，禁用“保本/稳赚/必涨”等表述；
3. **不自动通过准入**：风险等级只用于排序与提示，不得绕过人工尽调与审批；
4. **不将传闻作结论**：未验证信息单独标注，不与权威事实混排；
5. **不留存不必要的个人敏感信息**：最小化采集、分级授权、脱敏与访问审计；
6. **保留人工复核与申诉**：用户可查看来源、修改结论、反馈错误。

## 二、AI 幻觉与错误的责任划分

| 环节 | 责任主体 | 机制 |
|---|---|---|
| 数据采集 | 系统 | 记录来源、时点、口径；缺失即降级 |
| 事实抽取 | 系统 + 人工抽检 | 引用强制，禁止无源结论 |
| 风险推断 | 系统（标注把握度） | 推断与事实分栏 |
| 正式结论 | **人工复核** | 高风险结论须人工确认后方可外发 |
| 最终决策 | 用户 / 持牌人员 | 产品不做决策 |

**出错时**：可通过审计链路定位到“哪一步、用哪个版本模型、依据哪条证据”，支持回退与申诉。

## 三、失败条件（明文）

- 数据缺失 / 接口失败 → 输出“待核实”，**不得静默判正常**；
- LLM 不可用 / 超权限 → 降级为本地保守规则并标注；
- 来源仅摘录无全文 → `partial`，不得作唯一关键证据；
- 证据冲突 → 并列展示支持/反对，不自动择一；
- 提示词注入 / 恶意网页 / 越权查询 → 拦截并记录。

## 四、题面「统一规则」逐条落实

| 规则 | 落实 |
|---|---|
| 不输出确定性涨跌预测、收益承诺、买卖建议 | 产品设计 + 禁用词校验 + 冒烟测试断言（第 12 项） |
| 事实、推断与不确定信息必须区分 | 「AI 证据链」四栏结构 |
| 核心结论可回到原始字段/原文 | 证据带 `source_id/observed_at/origin_url/excerpt/status` |
| 明确来源、时点、单位、统计口径 | `docs/04_数据来源与口径.md` |
| 数据缺失/冲突/过期/失败不得静默生成“正常” | 缺失=`unavailable`+待核实；冲突=并列；降级=显式标注 |
| 不得提交 API Key / 隐私 / 受限数据 | 已删 cookie、真实名单、历史库；配置仅模板；`.gitignore` 忽略密钥 |

## 五、答辩预设问答

**Q1：为什么这是投资产品，而不是普通风控工具？**
风险洞察直接服务黄金授信、企业套保与贵金属产品适配；输出不仅是内部筛查结果，还包括客户可读的风险说明与投资情景。风险控制是产品可信度的一部分，而非终点。

**Q2：AI 的不可替代性是什么？**
规则判断已知条件，搜索返回链接；本产品需要 AI 在多源信息间建立“事件—企业/产品—黄金”的关系、解释影响路径，并按受众生成不同深度的合规表达。

**Q3：如何防止模型胡说？**
限定来源检索、引用强制、事实/推断分栏、规则校验、人工复核与审计日志；无可靠证据时输出“待核实”而非强行生成结论。

**Q4：项目是否已上线？**
当前是可交付的产品方案与原型验证项目，以构造/脱敏数据完成 MVP；正式上线与业务指标需经试点验证，本包不将其表述为既成结果。

**Q5：为什么不能直接用规则或搜索替代？**
见 `docs/01_产品说明与设计.md` 第五节对比表：语义理解、跨文档推理、合规表达生成与可追溯审计是规则/搜索做不到的。
