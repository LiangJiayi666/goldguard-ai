# 04 · 数据来源与口径

## 一、总原则

1. **宁缺毋滥**：无法取得可靠来源时输出“待核实”，不臆造；
2. **可追溯**：每条证据必须能回到来源、观察时点、口径；
3. **事实/推断分离**：事实证据与模型推断分栏，推断标注依据与把握度；
4. **口径一致**：同名指标需标明主体、报告期、单位、合并口径。

## 二、离线演示产品的数据

- 文件：`01_可运行Web产品_离线演示/data/fixtures.json`；
- 性质：**全部为构造/脱敏数据**，企业名（“示例企业A…H”）、域名（`*.invalid`）、社媒账号、证据文本均系虚构，不对应任何真实主体；
- 时刻：`generated_at = 2026-10-06 10:00:00`，冻结可复现；
- 来源登记（`sources`）：工信部 ICP 备案公开查询、企业官网公开页面、社媒公开主页、公开新闻/公告检索——均以“构造响应/构造快照”标注，URL 使用示例域名。

**证据字段口径**

| 字段 | 含义 | 取值/约定 |
|---|---|---|
| `id` | 证据编号 | E1, E2, … |
| `claim` | 该证据支持的结论 | 一句话 |
| `source_id` | 来源登记键 | 指向 `sources` |
| `excerpt` | 原文摘录 | 不拼接、不伪造全文 |
| `observed_at` | 观察时点 | ISO 8601，含时区 |
| `origin_url` | 原始入口 | 可缺；缺则 `status=partial` |
| `status` | 证据状态 | `verified` / `partial` / `unavailable` |

## 三、原版完整工程的真实数据来源

| 数据类型 | 来源 | 说明 |
|---|---|---|
| ICP 备案（网站/小程序/APP/快应用） | 工信部政务服务平台公开查询 | 经 `ICP_Query` 子工程；含验证码识别 |
| 企业官网 | 搜索 + 站点抓取 + 截图 | Playwright |
| 图片文字 | 官网/社媒截图 | PaddleOCR |
| 社媒账号与内容 | 抖音/快手/小红书公开主页 | 需登录态；仅抓公开内容 |
| 新闻/公告/舆情 | 公开检索 | 用于事件与风险补证 |
| 风险研判 | LLM + 关键词规则 | 结构化输出，规则与合规校验后采用 |

## 四、单位与时区

- 时区：`Asia/Shanghai`；
- 金额：人民币元（原版未涉及跨币种换算）；
- 时间戳：原版结构化接口为毫秒 Unix 时间；本演示统一为可读时间 + 时区。

## 五、失败与降级对结论的影响

| 触发 | 处理 | 结论标记 |
|---|---|---|
| 数据缺失 / 检索无结果 | 不判“正常” | **待核实**，证据 `unavailable` |
| 仅有摘录、无原文入口 | 不升级为原文 | `partial`，不得作唯一关键证据 |
| LLM 不可用 | 降级本地关键词规则 | `conservative_local_fallback`，标注把握度低 |
| 来源冲突 | 不自动择一 | 并列展示，要求人工复核 |
| 接口限流/超时 | 退避重试；用缓存须带时点 | 无缓存=`unavailable`；有缓存=`partial` |

## 六、可选扩展：扶摇 / iFinD 数据接入（未在本演示中调用）

题面允许使用扶摇金融数据 API / MCP 与 iFinD MCP。本产品未来可按以下边界接入，用于**企业财务与企业画像的结构化补证**：

- **扶摇**：标的消歧、行情/K 线、三表、财务指标、估值、指数/板块成分——用于回答“这家企业是否上市、财务是否恶化”；
- **iFinD MCP**：公告/新闻语义检索、行业与宏观——用于获取原始材料段落（注意其返回“相关段落”而非全文，无原文链接时须标 `partial`）；
- 接入原则：仅服务端调用、密钥只放 Secret、浏览器不直连、取数先校验时间/标的/口径。

> 本提交包未包含任何密钥；如后续接入，请将 Key 放入部署平台 Secret 并在 `.env` 中管理（已在 `.gitignore` 忽略）。
