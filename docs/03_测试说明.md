# 03 · 测试说明

覆盖题面要求的三类场景：**主链路、数据缺失/接口失败、极端与合规边界**。

## 一、自动化测试（推荐先跑）

```bash
cd 01_可运行Web产品_离线演示
python tests/smoke_test.py       # 期望：冒烟测试 19/19 通过
```

该脚本仅用标准库：启动服务 → 逐个断言 → 关闭服务；返回码 0 表示全部通过。

**断言清单（19 项）**

| # | 场景 | 断言 |
|---|---|---|
| 1 | 启动 | 服务启动并返回元数据 |
| 2 | 主链路 | 驾驶舱返回 8 家企业 |
| 3 | 可追溯 | 企业A 至少 3 条事实证据 |
| 4 | 可追溯 | 每条证据都能回到已登记来源 |
| 5 | 可追溯 | 每条证据都有观察时点 |
| 6 | 可追溯 | 证据状态取值合法（verified/partial/unavailable） |
| 7 | 结构 | 事实/推断/不确定项/改变结论条件分栏存在 |
| 8 | **数据缺失** | 企业G 风险结论为“待核实”（None），未误判为无风险 |
| 9 | **数据缺失** | 企业G 存在 unavailable 证据节点 |
| 10 | **失败降级** | 企业H 标记为降级模式 |
| 11 | **失败降级** | 企业H 在不确定项中披露降级事实 |
| 12 | **合规边界** | 数据中不含收益承诺/买卖指令表述 |
| 13 | **合规边界** | 产品显著声明不构成投资建议 |
| 14 | 人机协作 | 人工复核可提交并生效 |
| 15 | 人机协作 | 复核结果写回证据卡片 |
| 16 | 主链路 | 可启动排查任务 |
| 17 | 主链路 | 启动后状态为运行中 |
| 18 | 主链路 | 可停止排查任务 |
| 19 | 主链路 | 停止后状态为已停止 |

## 二、手工验收用例

| 用例 | 步骤 | 预期 |
|---|---|---|
| 主链路 | 打开首页 → 点「开始排查」 | 12 阶段按序推进，日志实时滚动；结束后状态回到“已停止” |
| 企业证据链 | 点任一企业 →「AI 证据链」 | 事实证据 / 推断 / 不确定项 / 改变结论条件 四栏齐全；证据含来源与时点 |
| 人工复核 | 点「修改」 | 弹窗输入意见 → 卡片显示“已复核·修改”，日志出现复核记录 |
| 数据缺失 | 打开「示例企业G」 | 结论=待核实，证据节点 `unavailable`，建议“补充工商全称后重检” |
| 模型降级 | 打开「示例企业H」 | 分析模式=本地规则降级，不确定项披露“LLM 不可用” |
| 界面健壮 | 断网后刷新页面 | 页面与数据仍可用（离线数据，不依赖外网） |
| 部署冒烟 | `python run.py --host 0.0.0.0 --port 8000` | 局域网/容器可访问 |

## 四、极端与故障注入建议（可扩展）

| 注入点 | 方法 | 期望 |
|---|---|---|
| 接口超时/失败 | 在原版中模拟 ICP/OCR 服务不可用 | 任务标 error/终态，不静默成功；看板红字提示 |
| LLM 401/限流 | 填错误 key 或模拟 429 | 走降级或重试，不输出无依据结论 |
| 来源缺失 | 证据无 `origin_url` | 状态降为 `partial`，禁止作唯一关键证据 |
| 证据冲突 | 两来源对同一指标不一致 | 并列展示，标记冲突，要求复核 |
| 合规话术 | 输入“保本高收益”文本 | 命中风险词并给出合规提示，不生成收益承诺 |

## 五、已知限制

- 离线演示产品的运行推进是**确定性模拟**，不进行真实抓取；
- 冒烟测试针对离线演示产品；原版全链路测试需完整环境（Windows + 依赖 + 登录态 + LLM Key）。
