# 01 · 产品说明与设计

## 一、一句话定位

**GoldGuard AI** 是面向黄金产业链与黄金投资场景的 **AI 原生风险雷达与合规证据引擎**：
把备案、官网、社媒、公告、舆情等碎片信息，转成**可解释、可追溯、可人工复核**的风险卡片，
服务黄金企业的授信/尽调与黄金产品的合规风险揭示。

> 它不替代投顾、不承诺收益、不给买卖指令；风险控制是产品可信度的一部分，而不是产品终点。

## 二、为什么值得解决（问题与机会）

黄金一端连着投资（金价、宏观、避险），另一端连着产业链企业（珠宝、回收、精炼、贸易）。现实中两端信息割裂：

| 用户 | 当前做法 | 问题 |
|---|---|---|
| 黄金企业客户经理 | 人工搜索、电话访谈、Excel | 尽调周期长，企业风险变化无法持续跟踪 |
| 合规/风控岗 | 抽查材料、手工留痕 | 证据分散、口径不一、复核成本高 |
| 贵金属投顾/产品经理 | 固定模板 + 历史报告 | 风险揭示同质化，难匹配客户画像 |
| 黄金投资者 | 浏览资讯、凭经验 | 信息噪声大，无法判断事件传导路径 |

传统工具不够：**搜索只给链接、规则只命关键词、静态报告解释不了“为什么影响、下一步核验什么”**。

## 三、目标用户与非目标

**目标用户**：黄金企业客户经理、贵金属投顾/产品经理、合规与审计人员（机构侧优先）。

**非目标（明确不做）**
1. 不做确定性涨跌预测、不承诺收益、不提供个性化买卖指令；
2. 不自动通过授信/客户准入，评分只用于排序与提示；
3. 不把网络传闻当结论，不把模型推断伪装成事实；
4. 本阶段不使用真实客户敏感数据。

## 四、成功标准（MVP 验收目标，均待实测）

| 指标 | 目标 | 验证方式 |
|---|---:|---|
| 单企业初筛耗时 | 较人工下降 ≥50% | 任务计时对比 |
| 风险卡片引用完整率 | ≥95% | 抽样人工审核 |
| 高风险事件召回率 | ≥90% | 标注集评测 |
| 正式输出人工复核覆盖率 | 100% | 审计日志 |
| 无依据结论率 | ≤3% | 红队 + 抽样 |
| 用户有效采纳率 | ≥60% | 复核结果统计 |

以上为**设计阶段验收目标，不作为已发生的业务结果**。

## 五、为什么必须是 LLM / Agent（AI 增量价值）

| 能力维度 | 规则引擎 | 搜索引擎 | GoldGuard AI |
|---|---|---|---|
| 多源召回与去重 | 仅预设关键词 | 返回链接，不结构化 | 多源召回 + 去重 + 实体对齐 |
| 语义/话术理解 | 否 | 否 | 识别“保本 / 高息回购 / 到期兑付”等类资金池话术 |
| 跨文档推理 | 否 | 否 | 建立 事件 → 企业/产品/黄金 的传导链 |
| 生成合规表达 | 模板固定 | 否 | 同源多表达，措辞经合规校验 |
| 可追溯审计 | 部分 | 否 | 每条结论回指来源、时点、口径 |
| 异常处理 | 硬阈值 | 无 | 缺失→待核实、不可用→降级并标注 |

**结论**：规则能判断已知条件，搜索能找到链接，但只有 LLM/Agent 能在多源信息间建立关系、解释传导路径、并按不同受众生成不同深度的合规表达。

## 六、产品模块

- **A 事件 / 风险雷达**：归并备案、官网、社媒、公告、舆情，自动去重、实体识别、影响方向判断。
- **B 企业风险画像**：工商/经营/上下游/诉讼处罚/舆情/交易行为；不是单一分数，而是“风险项—证据—影响—建议动作”。
- **C 黄金情景引擎**：把宏观事件映射为金价、波动率、流动性与企业经营的多条传导路径，输出基准/压力/极端三类情景，明确假设与不确定性。
- **D 合规协同助手**：按客户类型/产品/流程生成风险揭示、尽调问题清单、客户沟通稿、审批摘要，引用当前有效规则并标注需人工确认项。
- **E 审计与反馈中心**：记录输入时点、来源、模型版本、提示词模板、人工修改与最终结论；误报/漏报反馈进入评测集。

## 七、AI 原生工作流（数据—工具—状态—反馈闭环）

```text
用户问题 / 新增企业
   ↓ 任务分解 Agent：识别对象、时间范围、风险主题、输出格式
   ↓ 检索 Agent：召回备案、官网、社媒、公告、规则
   ↓ 证据 Agent：去重、实体对齐、校验来源与时点（verified/partial/unavailable）
   ↓ 分析 Agent：建立 事件→黄金/企业/产品 传导链，区分事实与推断
   ↓ 合规 Agent：适当性、措辞、引用完整性；无可靠证据则拒答/降级
   ↓ 人工复核：采纳 / 修改 / 标记误报 / 转人工
   ↓ 输出：风险卡片 / 情景 / 客户说明 / 审批摘要 + 审计留痕
   ↓ 反馈回流：误报、漏报、修改进入评测集
```

AI 的价值体现在**任务编排、证据选择、跨文档推理、结构化输出、反馈学习**五个环节，而不是末端加个聊天框。

## 八、核心体验

1. **风险驾驶舱**：企业完成度、任务终态、成功/异常任务、历史复用；企业清单可搜索/筛选；实时日志。
2. **企业详情 → AI 证据链**：事实证据（来源/时点/原文摘录/状态）、推断（含把握度与依据）、不确定项、改变结论的条件、人工复核按钮。
3. **反例可视化**：数据缺失的企业显示“待核实”，模型降级的企业显式标注，避免“静默判正常”。

## 九、MVP 与实施路线

- **阶段一（当前）**：可演示 MVP——企业风险排查 + 证据链 + 人工复核闭环，使用构造/脱敏数据。
- **阶段二**：小范围试用——引入客户经理/投顾，观测召回率、采纳率、修改比例、生成时间、漏报情况，仅作内部辅助。
- **阶段三**：产品化——接入权限、规则版本管理、反馈评测平台与业务系统 API，形成企业风险雷达、投顾工作台、客户风险说明三类形态。

## 十、创新点

1. 从“搜信息”到“做判断”：检索—证据—传导—合规—输出串成闭环；
2. 从“一个分数”到“可追溯风险卡片”：每个风险等级对应来源、时点、影响路径与建议动作；
3. 从“一套模板”到“同源多表达”：同一组事实生成审批摘要/客户说明/投顾问答，共享证据与规则版本；
4. 从“上线即结束”到“反馈可学习”：人工修改与后续处置进入评测闭环。
